# Architecture

harborlab is an image factory and governance platform. Applications are only consumers: an application
provides a Dockerfile starting `FROM` a golden image and a workflow made of one `uses:` line to the
platform's reusable build workflow. Everything that makes an image trustworthy is owned by the platform.

## Image flow

```
dhi.io ──(verify DHI signature)──► GHA golden.yml ──► ghcr.io/…/golden/{python,java}   signed + SBOMs + SLSA
app dir ──► GHA build-image.yml (reusable, platform-owned) ──► ghcr.io/…/apps/*   signed + SBOMs + SLSA + Trivy
ghcr.io ──(Harbor pull replication)──► harbor/{golden,apps} ──webhook──► dt-bridge ──► Dependency-Track
Argo CD ──► Kyverno admission (build identity, catalog base, SBOM, labels, registry) + Pod Security ──► pods
Kubescape (scan, CIS, runtime alerts, runtime OpenVEX) ──► dt-bridge ──► Dependency-Track
Policy Reporter · Grafana (VictoriaMetrics, VictoriaLogs) ◄── Kyverno reports, audit log, alerts, posture metrics
```

1. **Golden images** (`images/golden/<name>`) are a thin layer on a Docker Hardened Image: governance labels
   (`org.opencontainers.image.*`, `io.harborlab.*`) and a non-root user. `golden.yml` verifies the DHI base
   signature, then calls `build-image.yml`. `images/catalog.yaml` is their single source of truth: name,
   version, digest, status (`supported`, `deprecated`, `eol`) and dates. `task catalog:generate` derives the
   Kyverno params ConfigMap `kyverno/golden-images` and [the catalog doc](golden-images.md) from it; the
   platform CI fails when they drift.
2. **Builds** go through `.github/workflows/build-image.yml`: Buildx build, SBOMs in CycloneDX and SPDX
   (syft), a SLSA v1 provenance recording the base image digest, a blocking Trivy scan that applies the
   VEX statements published with the base (`--vex oci`), then cosign keyless signing and attestation
   (Sigstore bundles, stored as OCI referrers) with the workflow's GitHub OIDC identity. Images are pushed to
   GHCR.
3. **Harbor** pull-replicates GHCR into the `golden` and `apps` projects every 15 minutes (the cosign
   referrers fallback tags `sha256-*` included), with immutable tags, retention, vulnerability scanning on
   push and deployment security. Its configuration is OpenTofu code (`tofu/harbor`, [ADR 0005](adr/0005-opentofu-goharbor-provider-over-harbor-cli.md)).
   Harbor also serves as a proxy cache for `docker.io`, `quay.io`, `ghcr.io`, `registry.k8s.io` and `dhi.io`
   behind transparent containerd mirrors ([ADR 0006](adr/0006-transparent-mirror-and-trust-tiers.md)).
4. **Admission** is Kyverno CEL policies ([ADR 0002](adr/0002-kyverno-cel-only-admission.md)) plus native Pod
   Security Admission, per trust tier (see the [threat model](THREAT-MODEL.md)).
5. **Triage**: each image pushed or replicated into Harbor triggers a webhook to `dt-bridge`, which uploads
   the SBOM attested at build time to Dependency-Track (project `<harbor project>/<repository>`, version = tag),
   and converts the DHI OpenVEX of the base named by the SLSA provenance into a CycloneDX VEX
   ([ADR 0004](adr/0004-dependency-track-and-dt-bridge.md)).
6. **Runtime**: the Kubescape operator scans images in the cluster with Grype, checks CIS/NSA controls,
   raises runtime alerts against container profiles, and produces runtime OpenVEX documents that
   `dt-bridge` forwards to Dependency-Track ([ADR 0003](adr/0003-kubescape-over-trivy-operator-and-falco.md)).
7. **Observability**: VictoriaMetrics scrapes the `dt-bridge` image posture metrics; VictoriaLogs collects
   every container log (Kubescape alerts included) and the API server audit log; Grafana shows the
   `image posture` dashboard; Policy Reporter UI lists Kyverno PolicyReports.

## Cluster

| Layer | Component | Where |
|---|---|---|
| Cluster | kind, single node `harborlab-control-plane`, containerd mirrors to Harbor | `platform/kind/cluster.yaml` |
| Network | Cilium (kube-proxy replacement), Gateway API on the host network, `*.127.0.0.1.nip.io` | `platform/bootstrap/cilium-values.yaml` |
| GitOps | Argo CD app of apps `root`, sync waves 0–4 | `platform/bootstrap`, `platform/apps` |
| PKI | Local CA generated by `task up`, used by cert-manager, trusted by containerd; trust-manager delivers its public certificate to workload namespaces (PEM + PKCS#12) | `platform/config` |
| Secrets | OpenBao (Kubernetes auth, one policy per consumer) + External Secrets, seeded from `.env` | `platform/config/openbao` |
| Databases | CloudNativePG, one single-instance cluster each for Harbor and Dependency-Track | `platform/harbor`, `platform/dependency-track` |
| Registry | Harbor, configured by OpenTofu with the `goharbor/harbor` provider | `platform/harbor`, `tofu/harbor` |
| Admission | Kyverno ≥ 1.19 CEL policies, Pod Security Admission | `policies/` |
| Triage | Dependency-Track 5.1, `dt-bridge` | `platform/dependency-track`, `apps/dt-bridge` |
| Runtime | Kubescape operator | `platform/apps/templates/kubescape.yaml` |
| Observability | metrics-server, VictoriaMetrics, VictoriaLogs, Grafana, Policy Reporter | `platform/observability`, `platform/apps/templates` |

Argo CD syncs the Applications of `root` by sync wave, each wave once the previous one is Healthy:
0 operators and OpenBao, 1 trust-manager and platform config (local CA), 2 Kyverno and Harbor, 3 Kyverno
policies, Kubescape and observability, 4 workloads. No workload object exists before admission does.

## Trust tiers

| Tier | Namespaces | Admission |
|---|---|---|
| Workload | labelled `harborlab.io/tier=workload` | Enforced: signature and attestations by `build-image.yml`, catalog base, labels, Harbor `golden`/`apps` only, Pod Security `restricted`, digest pinning |
| Platform | labelled `harborlab.io/tier=platform` | Audited: registry allow-list, vendor signatures (Kyverno, Cilium, Argo CD) |
| Bootstrap | `kube-system`, `cilium`, `argocd`, `kyverno` | Excluded by name |

## Workloads

| Workload | Purpose |
|---|---|
| `dt-bridge` (Python, FastAPI) | Harbor webhook → Dependency-Track SBOM and VEX upload, Kubescape VEX forwarding, image posture metrics; built through the golden path |
| `hello-java` (Spring Boot) | Second golden-path consumer (golden Java) |
| `runtime-demo` | Governed, shell-capable target of the runtime and admission demos, with an authored Kubescape profile |

## Repository layout

| Path | Content |
|---|---|
| `images/` | Golden image Dockerfiles and `catalog.yaml` |
| `apps/` | Application sources, each built by a one-line workflow |
| `.github/workflows/` | `build-image.yml` (reusable), golden, app, fixture, policy and platform CI workflows |
| `platform/` | kind, bootstrap Helm values, Argo CD Applications and platform manifests |
| `policies/` | Kyverno workload and platform policies and their generated params |
| `tofu/harbor/` | OpenTofu Harbor configuration |
| `scripts/` | Implementations of the Taskfile tasks |
| `tests/` | bats, `kyverno test` and Chainsaw suites, catalogued in `tests/CATALOG.md` |
